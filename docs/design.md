# Goodhand の完成像と設計

## 完成像

左手と前腕が自然なピースの固定ポーズを保ち、腕全体だけを回転させる。写実的な照明デモではなく、漫画・版画のように中間面、短い暗転、その反対側で戻る明面を意図的に構成する。止めたどの角度でも指の重なりが読め、回転で階調が砂嵐にならない。Rust 化や軽量化のために、この形と見た目を犠牲にしない。

- 292 は承認 283 の見え方を保存した回転動画。形状の参照であり元メッシュではない。
- 323 は 318 Base の診断動画。完成した作者階調と混ぜない。
- 326 の 2 枚は棄却された排他的白/暗部の試作。改善の既定値に採用しない。
- 194 の階調と写真は別途回収・確認する。見ていない写真を根拠にしない。
- 現在、元メッシュ、231 の形状修正データ、元の生成・描画コードは未回収。
- 元中立モデルは MakeHuman から切り出した左手と前腕だったという制作会話が残る。ただし版・人体設定・抽出範囲・変形設定は未確認。
- 保存された回転像から作る新しいメッシュは「再構成」。元データの復旧と呼ばない。輪郭だけから爪、接触面、凹みや見えない面を一意に決めることはできない。
- 原本は保全したまま別の作業ディレクトリを使う。公開リポジトリへ写真・原動画を自動で追加しない。

## 段階ゲート

1. **ポーズ。** 元データ探索を続け、見つからなければ保存動画と確認済み写真を制約に再構成する。まず中立的な灰色面で全周を示す。指の交差、薬指/小指と掌、親指の腹との接触、爪側を複数角度で確認する。輪郭一致だけで合格にしない。
2. **ドット。** 同じ構図、大きさ、軸、固定格子で再描画する。輪郭と点位置の一致を先に調べ、階調の創作で形の誤差を隠さない。
3. **Base。** 318 の抑えた階調に戻し、323 と同じ角度・時間で比較する。元の関数が未回収の間は推定値と明記する。
4. **小さな改善。** 中間面、短い暗転とその先の明面、接触影を一つずつ比較する。194 の小指にある明→短い暗転→下面の明を、一律の遮蔽暗化で消さない。326 は不採用のまま。
5. **Rust と端末。** 正しさを固定してから必要な仕事を減らす。逆回転を端末で表示し、静止・回転・リサイズ・終了後の端末復元を検証する。実機の表示と測定なしに「同じ」「速い」「下限」と言わない。

各段階で実物画像または動画を提示し、観測・推定・未確認を分ける。段階ゲートを飛ばした完成報告をしない。

## 責務と依存方向

単一 Rust crate を基本とする。小さな処理のために crate や階層を増やさない。ファイル名だけで入力から出力まで追える構造にする。

```text
Cargo.toml
Cargo.lock
README.md                 利用方法、現在の段階、検証した実行条件
src/
  lib.rs                  公開するデータ型と処理境界
  mesh.rs                 頂点・面・部位ラベルの検証と読込み
  view.rs                 固定した中心・大きさ・軸、角度と座標変換
  raster.rs               可視面、深度、法線。階調・端末を知らない
  tone.rs                 Base と作者の補正を別の値として計算
  dots.rs                 固定格子での面積平均、階調量子化
  terminal.rs             点フレームを端末の更新列へ変換、状態を復元
  main.rs                 引数、時刻、入力、処理の接続だけ
assets/
  hand.mesh               出自を明記した固定ポーズ。元メッシュとは区別
  provenance.json         形状・各パラメータの由来と未確定情報
tests/
  geometry.rs             不正データ、回転、接触/交差の検証
  render.rs               輪郭、点、階調、角度の回帰検証
  terminal.rs             差分更新と終了/エラー後の状態復元
tools/
  reconstruct.py          参照からの再構成。実行時依存にしない
  extract_reference.py    画像/動画の点配列と制約の検証
  measure.sh              条件付き計測と生成命令の記録
docs/
  design.md               本文
  recovery.md             回収物、ハッシュ、探索と未回収項目
  performance.md          必要な仕事、仮定、実測、命令との照合
```

これは設計先行の配置案。空のファイルや未実装 API を大量に作って進捗に見せない。実装前に必要な意味論を再点検し、責務が重複するなら構造自体を直す。

```text
Mesh + View
    ↓
SurfaceFrame { depth, normal, part }
    ↓
Base + AuthorAdjustment
    ↓
DotFrame { grid, mask, tone }
    ↓
TerminalEncoder + PreviousDotFrame
    ↓
更新バイト列
```

端末側はメッシュや照明を知らない。Base は写真や試作番号で分岐しない。作者補正は Base を破壊せず、別レイヤーとして無効化・比較できる。再構成用 Python、動画デコーダ、画像処理ライブラリは配布バイナリの依存に入れない。

### API が守ること

- `Mesh::validate` は範囲外の面、非有限座標、壊れたラベルを拒否する。自己交差・接触は単純な範囲検査とは別に検証する。
- `View::at_frame(frame, 288)` は同じ時刻なら同じ変換。経過フレーム数の累積で角度をずらさない。
- `rasterize(mesh, view, &mut surface)` は呼出し側が確保したバッファを再利用する。
- `shade(surface, style, &mut tone)` は Base のみと作者階調つきの双方を選べる。
- `sample_dots(tone, grid, &mut dots)` は固定した格子・画素占有の契約を守る。
- `encode(previous, current, viewport, &mut bytes)` は更新対象だけを出し、I/O を行わない。
- バイナリだけが標準入出力、時計、終了シグナルを扱う。

## 端末の見た目を同一と呼ぶ条件

1000 × 640 の動画、200 × 120 の点、端末の文字セルは別の単位である。通常の ANSI 文字描画はフォントとセル縦横比に依存するため、保存 PNG の 2 × 2 px 点をそのまま保証できない。論理格子は維持し、端末出力の物理的な大きさと階調を実機で照合する。必要な出力方式はこの照合後に決め、構図の変更や品質低下があるなら比較を示す。標準的な端末へ出したという理由だけで画像との一致を主張しない。

## 必要な仕事と条件付き下限

(T): 面数、(V): 頂点数、(P): raster の画素数、(N): 点数、(K): 変化した点数、(B): 出力バイト数。旧記録の値は (V=3007), (T=5922)、旧 raster は (P=800×480=384000)、点格子は (N=200×120=24000)。これらは現在の再構成メッシュの規模ではない。

- 毎フレーム全メッシュを回す方式なら座標変換は少なくとも入力 (V) の読取りが必要。ただし固定ポーズ・固定軸の事前計算で、実行時にその方式自体を除去できる。単なる演算の高速化を全体の下限と呼ばない。
- 深度ラスタは方式により可視候補面/被覆画素に仕事が必要。全画素の面積平均を採用すれば少なくとも (P) 相当の読取りが発生するが、必要な点の被覆だけを直接求める方式も比較する。
- 24 fps の全格子走査なら 576000 点判定/秒。差分出力でも通常は前後の状態確認が必要だが、変化集合を生成側で追跡できるなら全走査自体を削減できる。観測したデータがなければ優位を断定しない。
- 全点 1 byte の階調だけなら 24000 byte/フレーム、288 フレームで 6912000 byte。mask を別に持つ場合と sentinel に統合する場合、欠け/黒の区別を失わないか比較する。
- 元動画を再生するだけなら固定 288 フレームの事前計算でラスタを省けるが、任意角度、サイズ変更、作者階調の編集には弱い。完成したモデルを捨てて動画に置き換えない。
- 端末へ (B) byte 送る方式の転送だけの下限は、実測スループット (R) に対して (B/R)。ANSI の色・カーソル・UTF-8 の費用と terminal の描画費用は、Rust の計算時間と分ける。
- 許容速度は 1 周 12 秒・24 fps を維持すること。平均だけでなく長いフレームと deadline miss を測る。新しい fps・回転速度を勝手に仕様にしない。

計測表には CPU/OS/端末、build profile、target、mesh hash、解像度、表示方式、入力角度列を残す。構築/読込み、座標変換、ラスタ、階調、点化、符号化、write、端末での体感を分ける。ネイティブと Wasm は同一条件で比較できる部分だけ比較し、生成命令と境界費用も調べる。Rust だから速い、圧縮したから軽い、最速だったから真の下限という結論にしない。
